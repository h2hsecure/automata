# Design Spec: Form-to-Website Integration (Tracking Server)

**Date:** 2026-10-15
**Status:** Approved
**Reference:** [Web UI Phase 2 Design](2026-09-17-web-ui-phase2-design.md)
**Module:** `github.com/hekemen/automata`

---

## 1. Problem Statement

Forms created in the Web UI cannot be embedded on websites. The tracking server (port 8081, the public, unauthenticated surface) hosts the form routes, but:

1. **No context resolution on form routes.** `internal/adapter/tracking/server.go` registers `/form/list`, `/form/:id`, `/form/submit/:slug`, `/form/:id/submissions` with no middleware. The form handlers read `c.GetString("context_id")` and return **401** when it is empty — so every form request to the tracking server fails.
2. **No public form-definition endpoint.** The only definition route (`GET /form/:id`) requires a context ID in a header that a public page cannot know, and the main API's `/api/context/forms` requires Bearer auth.
3. **No embeddable snippet.** The tracking server serves a tracking snippet (`/snippet/:id.js`) but nothing that renders a form.
4. **Ingress gap.** The pweb ingress routes `/track` and `/snippet` to the tracking server but not `/form`.

Result: there is no way to put a working form on a website.

## 2. Goals

- Context resolution on the tracking server's form routes via an explicit, unambiguous mechanism (no guessing).
- A public form-definition endpoint that a page can fetch without auth.
- A self-rendering form snippet that renders the form fields and posts submissions to the tracking server.
- A one-line embed tag that website owners paste into their HTML.
- Ingress routing so the snippet is same-origin on pweb (no CORS).

## 3. Non-Goals

- Editing form submissions from a website.
- Cross-origin form embedding (CORS is intentionally not added; same-origin routing is the supported path).
- Fixing the banner/placement/campaign CRUD baseline failures (`banner_campaign_http` ×10) — those tests use a hand-rolled engine without middleware and are out of scope.

## 4. Architecture

### 4.1 Route map (tracking server, port 8081)

| Route | Auth | Context source | Handler |
|---|---|---|---|
| `GET /form/list` | none | middleware | `FormHandler.List` |
| `GET /form/:id` | none | middleware | `FormHandler.Get` |
| `POST /form/submit/:slug` | none | middleware | `FormHandler.SubmitForm` |
| `GET /form/:id/submissions` | none | middleware | `FormHandler.ListSubmissions` |
| `GET /form/definition/:contextID/:slug` | none | path | `FormSnippetHandler.ServeDefinition` |
| `GET /form/snippet/:contextID/:slug` | none | path | `FormSnippetHandler.ServeFormSnippet` |
| `GET /track/banner/list` | none | middleware | `BannerHandler.ListBanners` |
| `GET /track/banner/:id`, `/track/placement/:id`, `/track/campaign/:id` | none | unchanged | unchanged |
| `POST /track`, `POST /track/batch`, `GET /snippet/:id.js` | none | unchanged | unchanged |

### 4.2 Context middleware (new: `internal/adapter/tracking/context_middleware.go`)

```go
func ContextMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        contextID := c.GetHeader("X-Context-ID")
        if contextID == "" {
            contextID = c.Query("context_id")
        }
        if contextID != "" {
            c.Set("context_id", contextID)
        }
        c.Next()
    }
}
```

**Deliberate choices:**

- **Header → query param only.** No subdomain fallback and no default-context fallback. The existing `tracking.ResolveContext` (header → subdomain, 400 on failure) is *not* reused: `httptest.NewRequest` defaults `Host` to `example.com`, which would make subdomain resolution silently "succeed" in cicd tests, while `form_http_test.go` expects **401** for a missing header.
- **Fail-closed.** When neither source is present, `context_id` stays unset and the existing handlers respond with their own 401/400. No validation of the context ID is performed (the middleware has no repository); a bad ID simply 404s at form lookup.

### 4.3 Public form routes (new: `internal/adapter/tracking/form_snippet_handler.go`)

- `ServeDefinition` — `GET /form/definition/:contextID/:slug` → 200 with the form definition JSON (`GetBySlug`), 404 when the form does not exist. The payload is an explicit normalized object (`id`, `contextId`, `slug`, `name`, `description`, `fields`) — the domain `Form` struct has no JSON tags and serializes with capitalized keys (the main API's internal contract, which the Web UI reads as-is), so the public endpoint does not reuse it.
- `ServeFormSnippet` — `GET /form/snippet/:contextID/:slug` → 200 `application/javascript` with the self-rendering snippet (404 for unknown forms), generated by `snippet.GenerateForm(contextID, slug)`. A trailing `.js` on the slug is tolerated (the handler strips it), so `.js`-suffixed URLs keep working.

**Why static prefixes (`/form/definition/...`, `/form/snippet/...`):** gin's router panics when `/form/:contextID/:slug` is registered alongside the existing `/form/:id` — verified with a test program:

```
panic: ':contextID' in new path '/form/:contextID/:slug' conflicts with existing wildcard ':id' in existing prefix '/form/:id'
```

Static segments coexist with the `:id` wildcard (static wins on match), so the public routes keep the `/form` prefix and the pweb ingress needs a single `/form` Prefix route.

**Why no `.js` suffix in the snippet route:** gin v1.10.0's router matches `:slug.js` but captures the `slug` param as the *empty string* (verified with a throwaway program against the project's exact gin version) — the route shape is unusable. The canonical route is therefore suffix-less; `<script src>` does not require a `.js` extension, and the server sets `Content-Type: application/javascript`.

**Wiring without a signature change:** `NewServer` keeps its 5-argument signature (`formHandler, bannerHandler, placementHandler, campaignHandler, trackingRepo`) — `cicd/tracking_server_test.go` and `cicd/tracking_http_test.go` both call it with 5 args. `FormSnippetHandler` obtains the form repository through a new `FormHandler.Repo()` accessor.

### 4.4 Snippet (new: `pkg/snippet/form_generator.go`)

`GenerateForm(contextID, slug string) (string, error)` produces an IIFE that:

1. Fetches `/form/definition/<contextID>/<slug>` (same origin, no CORS needed).
2. Renders the form into a container: `[data-automata-form="<slug>"]` if present, else `#automata-form`, else `document.body`.
3. Renders fields by type: `text`, `email`, `tel`, `number`, `url` → `<input type=...>`; `textarea` → `<textarea>`; `select` → `<select>` with a placeholder option; unknown types fall back to `<input type="text">`. Required fields get `required`.
4. On submit: POSTs `{"data": {...}}` to `/form/submit/<slug>` with the `X-Context-ID` header (matches `SubmitFormBody`), disables the button, and shows success/error status text.
5. On definition-load failure: renders a "This form is not available right now." placeholder.

**Embed tag** (relative path — valid on hosts whose ingress routes `/form` to the tracking server):

```html
<script src="/form/snippet/<contextID>/<slug>"></script>
```

### 4.5 Ingress (cluster-only, not in the image)

pweb ingress (`pdaccess-web-pdaccess`, host `pweb.home.arpa`) gains one path:

- `/form` (Prefix) → `automata-tracking:8081` (the existing same-namespace shim Service with manual Endpoints)

All three public form paths (`/form/definition/...`, `/form/snippet/...`, `/form/submit/...`) are same-origin on pweb.

## 5. Data Model

No schema changes. `forms` and `form_submissions` are unchanged; `tracking_events` is untouched.

## 6. Security Considerations

- Public endpoints expose only **form definitions** (field slugs, labels, types) — never submissions. Submissions remain context-scoped via the middleware.
- The context ID (a UUID) is a capability: embedding a form in a public URL reveals that context's form definition. This is inherent to the approved design (the definition endpoint is unauthenticated).
- No auth token, cookie, or session is required by the snippet.

| Suite | Failures fixed | Why |

`webui/src/views/FormsView.vue` gains a per-form **Embed** action that shows the embed tag for the current context with a copy button. Rebuilt `web/` assets are committed alongside (repo convention).
